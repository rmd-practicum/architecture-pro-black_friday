## Задание 10.1

Критически важными с точки зрения целостности и скорости обработки являются:

- Заказы: пользователь должен получить те товары, которые были заказаны
- Корзины: пользователь должен видеть актуальное содержимое корзины, а также иметь возможность быстро добавлять и убирать товары

Применение Cassandra имеет смысл для:

- Сессий: большой объем записываемых и читаемых данных, требуется масштабируемость (например, для резкого роста трафика в Черную пятницу); данные сессий можно распределить по регионам для лучшей локальности
- Историй заказов: также большой объем записываемых данных, при этом eventual consistency не является проблемой — актуальность данных в истории не так критична

## Задание 10.2

Для partition key сессий используем уникальный идентификатор сессии: это даст равномерное распределение данных по нодам. Кластерные ключи не нужны: доступ нужен к одной конкретной сессии по идентификатору.

```
CREATE TABLE sessions (
  session_id   uuid,
  user_id      text,
  created_at   timestamp,
  last_seen_at timestamp,
  PRIMARY KEY  (session_id)
);
```

Для partition key истории ордеров используем уникальный идентификатор пользователя. Кластерный ключ created_at позволит получать историю заказов в хронологическом порядке.

```
CREATE TYPE order_item (
  product_id   text,
  product_name text,
  quantity     int,
  price        decimal
);

CREATE TABLE orders_by_user (
  user_id     text,
  order_id    text,
  created_at  timestamp,
  status      text,
  total       decimal,
  items       frozen<list<order_item>>,
  PRIMARY KEY (user_id, created_at)
);
```

## Задание 10.3

- Hinted handoff: используем и для сессий, и для историй заказов; не влияет на latency запросов
- Read repair:
  - Сессии: не используем, так как увеличивает latency (критично для сессий), но при этом время жизни сессий довольно мало
  - Истории заказов: используем, так как целостность историй заказов важна, а увеличение времени получения истории не так критично
- Anti-entropy repair:
  - Сессии: не используем; старые сессии не нужны
  - Истории заказов: используем для восстановления старых (редко читаемых) заказов
